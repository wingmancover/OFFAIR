# OFFAIR 原型游玩与开发说明

默认地图为 `Content/OFFAIR/Levels/Lvl_Prototype.umap`。使用 UE 5.8 打开工程后运行 Play 即可进入。运行时使用蓝图，`Tools/unreal/` 下的 Python 仅用于编辑器资产生成和验证，不是游戏运行依赖。

## 不使用 GM 的完整路线

1. 在阶段 0 靠近青色核心，看向它并按 **E**。屏幕提示条件已锁定，此时世界仍处于阶段 0。
2. 按 **R** 主动结束本轮，或通过正常伤害死亡。复活后进入阶段 1；未取得核心就重试则仍回到阶段 0。
3. 穿过已打开的阶段门，在 300 cm 内看向手枪，出现 `[E] Pick up pistol` 后按 **E** 拾取；必须无遮挡，靠近或点击左键不会自动拾取。守卫在拿枪前待机，拾取成功后开始行动与攻击。使用鼠标左键击败守卫。
4. 靠近守卫死亡处悬浮的金色权限卡，看向它并按 **E** 拾取。
5. 前往南侧掩体后的蓝色终端，看向终端按 **E** 接入监控。
6. 用鼠标把监控转向侧墙，按 **E** 或 **Q** 返回本体。设备在本轮保持调整后的方向。
7. 沿红色监控通道进入绿色出口区域，完成原型。

如果监控发现本体，出口会在本轮锁定，按 R 重新尝试。复活会恢复敌人、武器、关键物品、权限、设备方向和警报。监控操作期间世界继续运行，本体停留原地且仍可受伤。

R 是正常游玩中的主动重试操作，不需要打开 GM。完成后再按 R 会从阶段 0 重新开始。当前不提供跨进程存档。

## 控制

| 输入 | 功能 |
| --- | --- |
| WASD、方向键 | 移动 |
| 鼠标 | 本体观察，或远程控制摄像机方向 |
| 空格 | 跳跃 |
| 鼠标左键 | 使用模板武器射击 |
| 左 Shift | 模板切枪；不是冲刺 |
| E | 枪械／关键物品／终端交互；监控中也可退出 |
| Q | 退出监控 |
| R | 正常重试；完成后从头开始 |
| F1 | 开关 GM 面板 |
| GM 打开时的 1–6 | 与面板六个按钮相同 |

在编辑器内先点击游戏视口取得输入焦点。编辑器的 Shift+F1 可释放鼠标，Esc 可结束 PIE。建议使用足够大的游戏视口；当前 HUD 是固定尺寸的英文灰盒界面，尚未制作响应式布局或本地化。

## GM 的边界

六个按钮分别为死亡、下一阶段、上一阶段、增加敌人、减少敌人、一键入侵监控。前后阶段是调试跳转，直接恢复目标阶段初始状态；首尾不环绕。

增加敌人上限为 8 个存活实例。减少优先处理后加入的敌人，且不产生击杀奖励。若用 GM 删除关键守卫，按 R 恢复阶段后再继续正常流程。

一键入侵可以绕过权限卡，但不会伪造权限卡或通关条件。正常入口、GM 和死亡共享阶段重建与监控清理逻辑。会话蓝图的 `GMEnabled` 配置及 `SetGMEnabled` 方法可关闭 GM，底层操作也会拒绝执行。

## 已复用与新增的部分

FPS 玩家继承 `BP_ShooterCharacter`，控制器继承 `BP_ShooterPlayerController`，游戏模式继承 `BP_ShooterGameMode`；原模板资产保持不变。武器、拾取、投射物、敌人及 StateTree 继续复用模板。

项目派生角色将死亡交给 `BP_RunDirector`，派生控制器抑制模板销毁角色后自动重生的回调，避免世界重置时出现第二个玩家。原型守卫移动速度调为 220，其他基础武器与血量沿用模板。弹药耗尽自动回满弹匣仍是模板行为，没有新增手动换弹或有限备弹系统。

原型 Director 禁用地图枪械拾取点的自动碰撞拾取，按 E 时继续调用模板的武器授予接口。`WeaponInteractDistance` 可在 Director 的 `Stage Setup` 中调整，当前默认 300 cm；其他物品和终端仍为 230 cm。`WeaponCollected` 仅属于本轮，死亡或 GM 跳阶段后恢复未拾取，敌人重新待机。GM 新增敌人也遵循本轮拿枪前待机、拿枪后启动的规则；指定击杀条件测试阶段同样适用。

`BP_RunDirector` 管理当前关卡的状态与对象引用；`BP_OFFAIRSession` 仅保存跨地图重载的阶段、待生效阶段和运行编号。`BP_PrototypeHUD` 提供目标、交互提示和可点击的 GM 面板。关键场景引用在 Director 的 `Stage Setup` 分类中可见。

阶段 0 的条件支持 `ItemAcquired / Anchor` 与 `EnemyKilled / Guard` 两种配对，默认使用前者。后者会为阶段 0 打开战斗区并配置关键守卫，便于验证指定击杀条件。未知配对会显示配置错误并保持不可游玩状态。当前原型只有两个阶段，不是任意分支关卡编辑器。

## 构建与验证

在工程根目录执行：

```powershell
.\Tools\Run-Unreal.ps1 -Mode Build
.\Tools\Run-Unreal.ps1 -Mode Test
```

引擎安装路径不同可传 `-EngineRoot`。构建脚本使用 UE 官方资产、蓝图图表和地图 API，生成／更新 `Content/OFFAIR`；不会修改原模板。它会重建脚本管理的蓝图函数和地图中 `OF_` 前缀对象，手工编辑这些生成内容后应先把变更同步回作者脚本，再重新生成。

构建分两步：生成蓝图与地图，再在真实编辑器帧循环中完成导航注册与构建。导航验收要求关键区域能投影到可行走面，不能只看 Recast Actor 是否存在。

测试驱动通过真实角色移动、模板武器投射物和正常交互方法完成不开 GM 的路线，然后执行隔离的 GM 和异常状态用例。测试注入、GM 操作与正常路线分开记录。报告位于 `Saved/PrototypeBuild/` 和 `Saved/PrototypeTests/`；图形界面与真实键鼠检查另行记录，不能用脚本调用替代。
