# OFFAIR 原型游玩与开发说明

默认地图为 `Content/OFFAIR/Levels/Lvl_Prototype.umap`。使用 UE 5.8 打开工程后运行 Play 即可进入。运行时使用蓝图，`Tools/unreal/` 下的 Python 仅用于编辑器资产生成和验证，不是游戏运行依赖。

## 不使用 GM 的完整路线

1. 阶段 0 可以探索整个空间，原 StageGate 已移除，但不能提前通关。靠近地上的红色纸条，看向后按 **E**。
2. 中央显示系统错误；本体输入锁定三秒，随后自动死亡并复活进入阶段 1，无需按 R。此时底部心理对白显示三秒。
3. 前往原枪械位置，看向金色盒子按 **E**。盒子消失，一名敌人出现并立即攻击。本阶段玩家生命为 100，四次有效的模板子弹命中即可死亡；死亡后进入阶段 2。
4. 再次复活到初始点，出现第二段三秒心理对白；盒子位置变成浮空手枪。300 cm 内看向枪模型，出现 `[E] Pick up pistol` 后按 **E** 拾取。靠近或左键不会拾取；守卫拿枪前待机，拿枪后启动。玩家恢复正常 500 生命。
5. 使用鼠标左键击败守卫，靠近死亡处的金色权限卡，看向后按 **E** 拾取。
6. 在战斗区中央等能实际看到摄像头的位置，1500 cm 内无遮挡看向设备，出现上方 `[E] Hack camera` 后按 **E**。旧终端及标识已隐藏，不再使用。
7. 用鼠标把监控转向侧墙；向上移动鼠标向上看，向下移动向下看。按 **E** 或 **Q** 返回本体，本轮保留设备朝向。
8. 沿红色监控通道进入绿色出口区域，完成原型。

如果监控发现本体，出口会在本轮锁定，按 R 重新尝试。复活会恢复敌人、武器、关键物品、权限、设备方向和警报。监控操作期间世界继续运行，本体停留原地且仍可受伤。

R 是正常主动死亡重试，纸条三秒锁定期间会被拒绝。开盒前死亡重试 S1，开盒后死亡进入 S2；S2 死亡重试 S2。完成后按 R 从阶段 0 重新开始。当前不提供跨进程存档。三阶段初始状态、对白与保留边界见[叙事流程](design/narrative-prototype.md)。

## 控制

| 输入 | 功能 |
| --- | --- |
| WASD、方向键 | 移动 |
| 鼠标 | 本体观察，或远程控制摄像机方向 |
| 空格 | 跳跃 |
| 鼠标左键 | 使用模板武器射击 |
| 左 Shift | 模板切枪；不是冲刺 |
| E | 枪械／关键物品拾取、看向摄像头黑入；监控中也可退出 |
| Q | 退出监控 |
| R | 正常重试；完成后从头开始 |
| F1 | 开关 GM 面板 |
| GM 打开时的 1–6 | 与面板六个按钮相同 |

在编辑器内先点击游戏视口取得输入焦点。编辑器的 Shift+F1 可释放鼠标，Esc 可结束 PIE。建议使用足够大的游戏视口；当前 HUD 是固定尺寸的英文灰盒界面，尚未制作响应式布局或本地化。

## GM 的边界

六个按钮分别为死亡、下一阶段、上一阶段、增加敌人、减少敌人、一键入侵监控。前后阶段是调试跳转，直接恢复目标阶段初始状态；首尾不环绕。

增加敌人上限为 8 个存活实例。减少优先处理后加入的敌人，且不产生击杀奖励。若用 GM 删除关键守卫，按 R 恢复阶段后再继续正常流程。

一键入侵可以绕过权限卡，但不会伪造权限卡或通关条件。正常入口、GM 和死亡共享阶段重建与监控清理逻辑。会话蓝图的 `GMEnabled` 配置及 `SetGMEnabled` 方法可关闭 GM，底层操作也会拒绝执行。

## 已复用与新增的部分

FPS 玩家继承 `BP_ShooterCharacter`，控制器继承 `BP_ShooterPlayerController`，游戏模式继承 `BP_ShooterGameMode`；原模板资产保持不变。武器、拾取、投射物、敌人及 StateTree 继续复用模板。

项目派生角色将死亡交给 `BP_RunDirector`，派生控制器抑制模板销毁角色后自动重生的回调，避免世界重置时出现第二个玩家。原型守卫移动速度调为 220，其他基础武器与血量沿用模板。弹药耗尽自动回满弹匣仍是模板行为，没有新增手动换弹或有限备弹系统。

原型 Director 禁用地图枪械拾取点的自动碰撞拾取，按 E 时继续调用模板的武器授予接口。`WeaponInteractDistance` 可在 Director 的 `Stage Setup` 中调整，当前默认 300 cm；核心与权限卡为 230 cm，`CameraInteractDistance` 默认 1500 cm。枪械瞄准点取实际 StaticMesh 包围盒中心，摄像头取设备位置；朝向、距离和到目标点的 Visibility 射线共同判定交互。`WeaponCollected` 仅属于本轮，死亡或 GM 跳阶段后恢复未拾取，敌人重新待机。GM 新增敌人在正常战斗阶段同样拿枪前待机、拿枪后启动；S1 陷阱触发后本轮登记的敌人立即启动，不要求拿枪。

`CameraPromptVisible` 是即时界面状态，按视线和权限更新，黑入、打开 GM、失去目标或重置时清除，不跨循环保留。只有初次连接要求瞄准、距离和无遮挡；连接后转开设备不会因此断线。GM 继续绕过这些入口条件。旧终端、屏幕和标识保留资产引用，但在地图中隐藏并关闭碰撞；不再参与初始化必需引用校验。

`BP_RunDirector` 管理当前关卡的状态与对象引用；`BP_OFFAIRSession` 仅保存跨地图重载的阶段、待生效阶段和运行编号。`BP_PrototypeHUD` 提供目标、交互提示和可点击的 GM 面板。关键场景引用在 Director 的 `Stage Setup` 分类中可见。

阶段 0 默认条件仍为 `ItemAcquired / Anchor`，其目标现在是红色纸条。内部 `EnemyKilled / Guard` 配置保留作指定击杀条件回归夹具；它不是正常叙事路线，也不触发纸条系统提示。未知配对会显示配置错误并保持不可游玩。当前原型为 0、1、2 三个阶段，不是任意分支关卡编辑器。

## 构建与验证

在工程根目录执行：

```powershell
.\Tools\Run-Unreal.ps1 -Mode Build
.\Tools\Run-Unreal.ps1 -Mode Test
```

引擎安装路径不同可传 `-EngineRoot`。构建脚本使用 UE 官方资产、蓝图图表和地图 API，生成／更新 `Content/OFFAIR`；不会修改原模板。它会重建脚本管理的蓝图函数和地图中 `OF_` 前缀对象，手工编辑这些生成内容后应先把变更同步回作者脚本，再重新生成。

构建分两步：生成蓝图与地图，再在真实编辑器帧循环中完成导航注册与构建。导航验收要求关键区域能投影到可行走面，不能只看 Recast Actor 是否存在。

测试驱动通过真实角色移动、模板武器投射物和正常交互方法完成不开 GM 的路线，然后执行隔离的 GM 和异常状态用例。测试注入、GM 操作与正常路线分开记录。报告位于 `Saved/PrototypeBuild/` 和 `Saved/PrototypeTests/`；图形界面与真实键鼠检查另行记录，不能用脚本调用替代。
