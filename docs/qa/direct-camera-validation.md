# 直接黑入与枪械瞄准点验证

日期：2026-10-19。基线为用户已试玩、保存并提交的 `8ff948d`。本轮仅修正枪模型瞄准点、摄像头直接交互、俯仰方向与旧终端显示；不改灯光、翻越、正式死亡推进或跨循环保留规则。

## 改动

- 枪械交互取实际 `StaticMesh` 包围盒中心，跟随模型浮动与旋转；不再取底座所在的 Actor 原点。
- 取得守卫权限卡后，1500 cm 内看向摄像头且 Visibility 射线无遮挡，设备上方显示深色底板的 `[E] Hack camera`，按 E 直接连接。`CameraInteractDistance` 为可调暂定值。
- 正常 `EnterRemote` 入口再次校验视线、方向与距离；GM 可绕过这些入口门槛，其他清理及重置逻辑共用。
- 俯仰输入修正为鼠标向上看上、向下看下，保留原水平和俯仰限位。
- 地图内旧终端、屏幕及 `03 / Camera Link` 标识隐藏并关闭碰撞，保留旧引用以避免破坏已有资产；初始化不再要求终端。
- `CameraPromptVisible` 仅为本轮即时界面状态，每次反馈更新重新计算；进入远程、打开 GM、失去合法目标、死亡及阶段跳转会清除，不跨循环保留。权限和设备方向仍按原规则在死亡时重置。
- 作者脚本同步。编辑器定向更新只编译 Director 与 HUD，不重建关卡布局或导航；地图只隐藏上述三件旧对象。验证脚本在当前地图已打开时不再强制重载，避免丢弃用户尚未保存的地图修改。

## 验证

环境为本机 UE 5.8.3、Windows、有画面 PIE。Director 与 HUD 编译通过，最终 33 项集成检查全部通过，耗时 37.75 秒，见[原始结果](evidence/direct-camera-runtime-result.json)。其中正常路线不使用 GM，走通核心、死亡推进、E 拾枪、战斗、权限卡、直接黑入、退出与通关；独立边界用例覆盖枪模型可交互而底座不触发、无权限拒绝、正常黑入、看偏拒绝、1500 cm 外拒绝、通道侧墙遮挡、遮挡解除后提示恢复，以及十轮重置后旧终端三件对象仍隐藏且无碰撞。

已单独通过窗口 E 按键接入摄像头、Q 按键退出，并用操作系统鼠标运动检查上下方向：进入时 Pitch 为 -18°，鼠标向下后为约 -18.8166°，向上后回到 -18°。这些检查未用 `PanRemote` 函数调用替代实际鼠标运动。夹具使用 GM 准备 S1、正常伤害产生权限卡，再通过正常拾取入口取得卡并定位本体；不作为正常全程游玩的替代证据。

窗口输入状态见[按键与鼠标记录](evidence/direct-camera-input.json)，[原生截图](evidence/direct-camera-prompt.png)已检查设备上方提示位置、深色底板和文字可读性。最终测试日志未发现 Blueprint Runtime Error、Accessed None 或 Python Traceback；作者脚本 Python AST 与 Git diff 空白检查通过。没有因此声称已完成全地图灯光、显示缩放或所有分辨率适配。
