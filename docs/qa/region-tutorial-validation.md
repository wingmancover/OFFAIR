## 验证方式与证据

- 托管构建：`Tools/unrealsharp.py managed-build --engine-root Y:/UE_5.8` 成功。随后 `build_region_tutorial.py` 在独立 commandlet 中生成并编译蓝图。
- 集成：`Tools/unreal/validate_region_tutorial.py` 在隐藏编辑器 PIE 中运行。完整逐项结果见[集成结果](evidence/region-tutorial-runtime.json)。覆盖导航采样、蓝图编译、正常教学链条、GM、死亡与 B 回归及异常。
- 画面：`Tools/unreal/capture_region_tutorial.py` 使用 RenderOffscreen 生成 11 张 1600×900 的实际 PIE 截图；没有使用示意图代替运行画面。检查普通字体、武器、掉卡、C1 黑入、D1 开门、C2 初始与转向找到答案、普通玩家看不到答案、F1 面板。
- 本机完整日志与截图在忽略目录 `Saved/RegionTutorial/`。本页保留[普通游玩 UI](evidence/region-tutorial-ui.png)和[C2 初始画面](evidence/region-tutorial-c2-initial.png)，便于跨机器审阅。

## 实际覆盖

| 范围 | 方法 |
| --- | --- |
| 首次记忆与物品门槛 | 真实目标、距离与视线判定后调用 E 输入处理；三秒锁定、重复输入、复活记忆、直接跳过纸条取枪 |
| 两条枪分支 | E 装备实际模板武器；验证青色 2 名、琥珀色 8 名；重复交互不重复生成 |
| 正常战斗／掉卡链 | 原生 AI 移动与攻击产生玩家伤害；玩家实际武器生成子弹，对两名守卫逐发造成伤害直至清场，最后掉卡并 E 拾取 |
| 战斗测试的控制条件 | 为稳定检查子弹命中，AI 攻击检查之后暂停守卫 AI、移动到无遮挡射击位置。没有把自动瞄准夹具说成手动射击手感测试；重复死亡和 GM 无奖励分支另用显式伤害注入 |
| 黑入教学 | 取卡后看向 C1、E 进入；未转动退出不算完成；转动后正常退出开 D1；方向输入、回到本体、输入解除、设备销毁与远程死亡 |
| 通路 | 用 CharacterMovement 连续移动穿过开放 D1 和直角过道，到达谜题房；不是只传送到门后检查位置 |
| 死亡重置 | 枪库存、世界展示枪、卡、门、朝向、敌人、控制器、子弹清理；重复死亡只执行一次，旧尝试进度拒绝 |
| GM | 默认隐藏、关闭时快捷键无效；增加守卫计入清场、移除不算击杀且禁发卡；清场掉卡后不允许再加敌人 |
| B | 缺条件拒绝；GM 明确授予测试条件后看向终端 E 保存；死亡恢复真实枪库存和玩家进度、保留完成区域；新 PIE 清空会话 |
| C2 | 初始 yaw 20°、pitch −15°；预览转向不授予 C1 学习条件；未保存死亡后恢复初始方向 |
| 异常 | 设备失效退回本体，基准 Actor 被销毁时重置明确失败关闭，不以不完整世界继续 |

重复回归发现并修复了两个问题：守卫默认朝向背对玩家，使模板定向感知过晚启动；控制器的普通蓝图销毁调用被引擎忽略，导致循环后残留。现为生成时面向玩家，登记控制器并解除控制、通过生命周期到期销毁。没有修改模板蓝图或插件源码。

## 限制与待用户确认

- **没有发送桌面物理键鼠**，E／Q／F1／数字键的自动测试调用运行时输入处理，鼠标测试调用相同转向入口。用户仍需在实际游戏视口确认按键、鼠标上下方向、选枪与黑入准星容差、战斗难度。后台工作未接管前台鼠标或键盘。
- 音效资产已生成并接入；自动会话使用 `-nosound`，实际音量、听感需用户试听。
- 字体清晰度和布局检查分辨率为 1600×900；最终 UI 风格和更广泛分辨率适配留在第 5 步。
- 新地图暂时只验证普通路线到谜题房。B 的条件准备仍用 GM，不能称为正常解谜通关；真实射击谜题与错误答案死亡在第 4 步接入。新地图翻越仍未复用，空格当前普通跳跃。
- 未执行本轮打包、旧原型完整回归或 Mac 验证；旧模板资产及旧 `Lvl_Prototype` 没有本轮内容变更。
